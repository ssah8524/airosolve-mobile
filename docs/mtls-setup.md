# Mobile mTLS setup guide

This app uses mutual TLS (mTLS) when connecting to the Pi API server. Every
HTTPS request presents a client certificate in addition to the Firebase Bearer
token. The Pi verifies both.

## What you need before building

Two files go in `assets/certs/` locally. This directory is gitignored — never
commit cert material.

| File | Where it comes from |
|---|---|
| `assets/certs/client.p12` | Generated by `scripts/gen_certs.sh` in the airosolve Pi repo. Copy `config/certs/client.p12` to this folder. |
| `assets/certs/ca.crt` | Pi CA certificate. Copy `config/certs/ca.crt` from the Pi repo. |

```bash
# One-time setup (run from the mobile repo root)
mkdir -p assets/certs
cp /path/to/airosolve/config/certs/client.p12 assets/certs/
cp /path/to/airosolve/config/certs/ca.crt     assets/certs/
```

## EAS Secrets (set once per project)

```bash
# PKCS12_PASSWORD — the passphrase used when generating client.p12
eas secret:create --scope project --name PKCS12_PASSWORD --value "<passphrase>"

# PI_CA_FINGERPRINT — SHA-256 fingerprint of the Pi CA cert (no colons, uppercase)
openssl x509 -in assets/certs/ca.crt -fingerprint -sha256 -noout \
  | sed 's/://g' | cut -d= -f2
eas secret:create --scope project --name PI_CA_FINGERPRINT --value "<fingerprint>"
```

## Building

This app requires a **native dev build** — Expo Go does not support
`react-native-ssl-pinning`. Use EAS Build for distributed builds or run
locally with the Expo CLI.

```bash
# EAS internal build (distributed to clinicians via link)
eas build --profile development --platform ios
eas build --profile development --platform android

# Local native build (no EAS account needed, requires Xcode / Android Studio)
npx expo run:ios
npx expo run:android

# Dev build without TLS (for testing against a Pi without certs)
TLS_ENABLED=false npx expo run:ios
```

## Enabling full mTLS on the Pi

Once clinicians have the dev build, flip `require_client_cert` to `true` in
the Pi's `config/configurations.yaml` and restart the API server. The Pi will
then reject any connection that does not present the signed client certificate.

```yaml
tls:
  enabled: true
  require_client_cert: true   # ← change from false
```

## Cert rotation

When the client cert expires (default: 1 year from `gen_certs.sh`):
1. Re-run `scripts/gen_certs.sh` on the Pi to generate new certs.
2. Copy the new `client.p12` and `ca.crt` to `assets/certs/`.
3. Update the `PKCS12_PASSWORD` and `PI_CA_FINGERPRINT` EAS Secrets if changed.
4. Cut a new build and distribute to clinicians.
